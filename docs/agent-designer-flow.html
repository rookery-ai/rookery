What happens on stop · block · continue

The one rule that governs all of it: your built files are only ever removed by an explicit Discard, an agent Delete, or draft expiry (7 days). Nothing a build does to itself deletes them.

Block The build won't finish

The coder ran but the result wasn't presentable — a failed guardrail, a timeout, a usage limit, or the weak-model gate ("couldn't confirm the script runs").

  • Returns to Designing — not a dead end.
  • Files on disk are kept; the draft records the failure so the next attempt has context.
  • Your move: keep going (rebuild), keep it as-is (save anyway), or describe a change.
  • The message tells you which options apply.

Continue Move it forward

From Review, or after a block, you push the agent toward Saved.

  • approve / keep it as-is → saves: the draft_<name> dir is promoted to the real agent, draft cleared.
  • keep going / try again → another build pass, iterating in the same dir.
  • A change request → back to Designing, keeping the built work; the next build refines it.

Stop Step away or cancel

Three very different kinds of "stop" — only one deletes anything.

  • Navigate away mid-build: the build keeps running in the background; on return it reconnects to live progress.
  • Cancel → Save as draft: session ends, chat + files kept, resume anytime.
  • Cancel → Discard: draft + files removed — the only self-inflicted delete.
  • Server restart: live session lost, but chat + files persist; resume recovers the build straight to Review.
