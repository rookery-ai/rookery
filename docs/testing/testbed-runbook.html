    Host preparation

    ~20 min

    A completely new host. Nothing here is Rookery-specific yet except the last two steps — the point is to reach a verified, empty install you can trust as a baseline.

    Confirm the host and reach it over SSH

    Linux gives you the filesystem sandbox; macOS and Windows do not, and this runbook assumes Landlock is present.

    uname -srm && cat /etc/os-release | head -2
    WhyOff Linux, sandbox.Supported() is false and coder subprocesses run unconfined. Every isolation charter later assumes confinement is real.
    Open an SSH tunnel so localhost means the server

    This is the step that makes localhost OAuth work at all. Run it on your laptop, not the server, and leave it open for the whole runbook.

    ssh -L 8080:localhost:8080 <user>@<new-host>
    Read this before you start

    OAuth redirect URIs are resolved in your browser. If you browse to http://192.168.1.50:8080, Google is handed a private IP and refuses it. The tunnel makes http://localhost:8080 in your laptop's browser point at the server, so the URI Google receives is the one you registered.

    Everything from here on assumes you open Rookery at http://localhost:8080 and nothing else. Bookmark it now.

    Install Rookery
    curl -fsSL https://rookery.cloud/install.sh | sh

    The installer fetches the release archive for your platform, verifies it against the release's checksums.txt, puts the binary on PATH, and offers the four host tools.

    Under testAccept the host tools when offered. This is the real first-install path and you only get to walk it once.
    Pin the public URL to localhost

    Set it before the first run so every OAuth callback is built against it.

    export ROOKERY_PUBLIC_URL=http://localhost:8080
echo 'export ROOKERY_PUBLIC_URL=http://localhost:8080' >> ~/.bashrc
    Precedence

    The instance URL in owner settings overrides this variable. If a connect flow later builds the wrong callback, check owner settings before you doubt the environment.

    Install the browser runtime
    rookery browser install

    Node plus the Playwright driver (134 MB) and Chromium (389 MB). Needed for the JS-page and search-fallback charters.

    Linux only

    Chromium needs shared libraries afterwards. If the install names missing ones, install them and re-run before moving on.

    02

    Credentials & localhost OAuth

    ~45 min

    Gather everything before building workspaces — each item blocks one. Most of the time here is spent waiting on third parties, so start the slow ones first.

    Register the Google OAuth client — one redirect URI for the whole family

    In Google Cloud Console → Credentials → Create OAuth client ID → Web application. Add exactly this authorized redirect URI:

    http://localhost:8080/dashboard/connectors/services/callback/google
    This is the payoff of localhost

    Google accepts plain http only for loopback. On any other host it demands https, which on a home server means a reverse proxy and a real certificate. Through the tunnel, localhost is a first-class redirect target and none of that is needed.

    Rookery's own preflight agrees: localhost classifies as loopback, not as a reserved name, so Google's require_public_host policy passes and the Connect button is not blocked.

    One URI, not eight

    The redirect URI is scoped to the OAuth application, not the service. Gmail, Calendar, Drive, Sheets, Docs, Tasks and YouTube are aliased children of the google app, so they all call back to /callback/google. Registering one URI covers the family; each service still consents separately.

    Use the hostname localhost, not 127.0.0.1 — Google's web-application client type is fussier about the raw IP form.

    Create three Telegram bots

    Message @BotFather → /newbot, three times. Suggested names: …_personal_bot, …_testing_bot, …_work_bot.

    Why threeplatform_connections is unique per (workspace_id, platform). One token cannot serve two workspaces, so cross-workspace chat parity needs one bot each.
    Collect the API keys
    KeyForWhy it is on the list
    OpenRouterall threeThe coder's own key — nothing thinks without it
    A second LLM providerPersonal or WorkSo the three workspaces do not share one provider
    Stripe (test mode)TestingThe overbind fixture — see phase 06
    SendGrid or MailgunWork, TestingEmail send, and the public_write approval gate

    Open-Meteo and Wikipedia need no credential at all — they cover the keyless auth.kind: none path.

    Stand up an MCP server on the LAN

    Any HTTP MCP server with a static bearer token. Note its URL and token.

    Self-host it — do not point at a public one

    MCP deliberately bypasses the private-address dial guard, exactly like connectors, so a LAN address works. The decisive advantage is that you can change its tool list on purpose — the only way to test that first-sync tools arrive enabled while later-sync tools arrive disabled, that a vanished tool is marked missing rather than deleted, and that an over-cap list says how many were held back.

    A third-party server you cannot mutate tests about half of this surface.

    Fresh groundZero MCP servers have ever been configured on a Rookery install. This whole area is unexercised.

    06

    The deliberate fixtures

    ~30 min

    Seven shapes built on purpose. Two of them cannot be produced through the interface at all — which is exactly the point: they are the shapes that arrive from migration and from model error, not from a user.

    F1 — the credential overbind fixture

    In Testing, the Stripe connection's account label must be literally test. Then build a DNS or uptime watchdog agent and let the model write a connections header containing the word "test".

    What must happen

    Stripe must not be bound. A binding is a grant of live payment credentials. The recorded bug matched the substring test against a short shared identity and gave a DNS watchdog the owner's Stripe access. TC-BIND-1

    F2 — an empty schedule timezone

    Create a schedule normally, then blank its timezone directly in the database.

    UPDATE agent_schedules SET timezone='' WHERE agent_id='<id>';
    Why SQLEvery new schedule now writes a zone, so this row cannot arise from the interface. That is precisely the pre-migration shape under test: empty must mean the host's local zone, and must not re-time a schedule that was already correct. TC-TZ-5
    F3 — a corrupted agent state file

    Take a working agent's state.md and move its JSON one line below the fence. Then run the agent.

    The most expensive bug on record

    This exact shape made agents conclude they had never run, re-derive a baseline and go silent — permanently, invisibly, with exit 0 and no warnings, at roughly 930k tokens an hour. It must now recover, re-render the file canonically, and preserve any prose notes. TC-RUN-9

    F4–F7 — the remaining four
    • F4 — a file of exactly 1 MiB and one of 1 MiB + 1 byte (file-kind boundary)
    • F5 — a file of raw non-UTF8 bytes (binary download-only panel)
    • F6 — several google_* connections all carrying the same address, so a family identity must not bind the whole family TC-BIND-2
    • F7 — fixture B1 itself, already generated in phase 05

    W10 — the agent designer charter

    The centerpiece, and the reason everything else runs first.

    Budget before you start

    A create build now runs a dry run — it executes the finished agent once before showing it to you. One measured build exceeded 1.5M tokens. Finding a broken connector during an expensive build wastes the build, which is why W5 and W6 come first.

    Test the cheap paths with aborted builds — approval-word matching, the plan-ready signal appearing and retracting, the blank-bubble case, and the dead-end invariant. Only the twelve scenarios run to completion.

    The one people missExpected
    Reply "Approved" at the review gateIt must save. If the word is unmatched it does not fail — it silently rebuilds, and nothing reports that.
    Scroll up during a long buildThe action bar stays reachable. This was diagnosed twice as logic and was layout.
    In every reachable stateA button is visible or the composer is usable. Never neither.
    Record what each run cost
    grep "agentrunner: run finished" logs/server.log
grep "build_id=<id>"            logs/server.log
grep "chat: turn finished"        logs/server.log
    Not only a test resultThe portfolio's total token spend answers whether the designer is something people use casually or ration — which is a launch-copy fact worth knowing before you write the launch copy.
